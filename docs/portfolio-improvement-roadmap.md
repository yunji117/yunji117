# 김윤지 포트폴리오 개선 로드맵

> 목적: 일반 방문자, 채용 담당자, 개발 면접관, 웹디자인 면접관이 김윤지의 역할과 강점, 프로젝트 성과를 빠르게 이해할 수 있는 포트폴리오로 개선한다.

## 문서 사용 방법

- 상태: `대기` → `진행 중` → `검토` → `완료`
- 우선순위: `P0 필수` / `P1 중요` / `P2 개선`
- 한 번에 하나의 Phase만 진행한다.
- 디자인 변경보다 콘텐츠 구조와 신뢰도 개선을 먼저 진행한다.
- 각 작업은 아래의 완료 기준을 충족하면 완료로 표시한다.

## 핵심 목표

- 방문자가 10초 안에 지원 직무와 핵심 강점을 이해한다.
- 채용 담당자가 30초 안에 대표 프로젝트와 성과를 확인한다.
- 개발 면접관이 역할, 기술 선택, 문제 해결 과정과 코드를 확인한다.
- 디자인 면접관이 문제 정의, 디자인 과정, 최종 결과와 실무 적용 사례를 확인한다.
- 모바일과 키보드 환경에서도 모든 핵심 콘텐츠를 탐색할 수 있다.

## 현재 포트폴리오의 강점

- 개발과 디자인 결과물을 함께 보여줄 수 있다.
- React, TypeScript, Next.js, Supabase, Figma 등 폭넓은 경험이 있다.
- 프로젝트별 개요, 목표, 기술, 문제 해결, 이미지 자료가 이미 준비되어 있다.
- 실제 배포 서비스와 커머스 게시 결과물이 있다.
- 상세페이지 126개 제작처럼 숫자로 증명할 수 있는 실무 경험이 있다.
- 포트폴리오 콘텐츠와 프로젝트를 관리할 수 있는 관리자 기능이 구현되어 있다.

## 가장 중요한 개선 방향

1. 첫 화면에서 지원 직무와 차별점을 명확히 전달한다.
2. 대표 프로젝트 3개를 먼저 보여준다.
3. 프로젝트마다 기간, 역할, 기여도, 성과를 추가한다.
4. 학습 중심 자기소개를 현재의 실행 경험 중심으로 바꾼다.
5. 기술 목록을 주력 기술과 사용 경험으로 구분한다.
6. 이력서, GitHub, 이메일 등 채용 행동으로 이어지는 경로를 강화한다.
7. 모바일 탐색, 접근성, 이미지 성능과 SEO를 개선한다.

# Phase 1. 포지셔닝과 콘텐츠 방향 확정

**우선순위:** P0 필수  
**상태:** 대기

## 1-1. 지원 직무 결정

- [ ] 가장 우선하는 지원 직무를 정한다.
- [ ] 프론트엔드 개발자 중심인지, 웹디자이너 중심인지, 두 역량을 결합한 직무인지 정한다.
- [ ] 이력서와 포트폴리오에서 같은 명칭을 사용한다.

### 선택안

- 프론트엔드 중심: `사용자 경험을 설계하고 React로 구현하는 프론트엔드 개발자`
- 개발·디자인 결합: `디자인 의도를 이해하고 실제 서비스로 구현하는 프론트엔드 개발자`
- 디자인 중심: `사용자의 구매와 행동 흐름을 설계하는 웹디자이너`

### 완료 기준

- 한 문장으로 “무슨 직무를 원하는지” 설명할 수 있다.
- Hero, About, 이력서, GitHub 소개의 직무 표현이 일치한다.

## 1-2. 핵심 강점 3개 선정

- [ ] 아래 후보 중 실제로 증명 가능한 강점 3개만 선택한다.

### 강점 후보

- 기획과 디자인을 실제 웹 인터페이스로 구현하는 능력
- React와 TypeScript 기반 프론트엔드 개발
- 배포 이후 운영까지 고려한 서비스 제작
- 사용자와 관리자의 전체 사용 흐름 설계
- 새로운 업무를 빠르게 학습해 결과물로 만드는 실행력
- 개발과 디자인 담당자 사이의 의도를 연결하는 커뮤니케이션

### 완료 기준

- 각 강점마다 증명할 프로젝트 또는 성과가 하나 이상 연결된다.
- “성실함”, “열정”처럼 증거가 모호한 표현만 사용하지 않는다.

보조 문구:

### 완료 기준

- 처음 방문한 사람이 10초 안에 이름, 지원 직무, 핵심 역량을 말할 수 있다.
- 주요 CTA가 스크롤 없이 보인다.
- 모바일과 PC에서 텍스트 및 캐릭터 이미지의 시각적 균형이 유지된다.

# Phase 3. 대표 프로젝트 구성

**우선순위:** P0 필수  
**상태:** 대기

## 3-1. 대표 프로젝트 3개 선정

- [ ] 지원 직무와 가장 가까운 프로젝트를 선택한다.
- [ ] 기술적 깊이, 실제 운영, 시각적 완성도를 각각 보여주는 조합으로 구성한다.
- [ ] 나머지 프로젝트는 `전체 프로젝트` 또는 `Archive`로 분리한다.

### 개발 직무 추천 조합

1. 논산 부동산 매물 플랫폼
2. 부동산 중개보수 계산기
3. DayTime 또는 Typing in Sheets

### 디자인·콘텐츠 직무 추천 조합

1. 커머스 상세페이지 디자인
2. 사용자 흐름이 잘 드러나는 웹 프로젝트
3. 개발까지 연결한 개인 프로젝트

### 완료 기준

- 대표 프로젝트마다 서로 다른 강점을 증명한다.
- 첫 화면 다음 영역에서 대표 프로젝트를 바로 확인할 수 있다.
- 대표 프로젝트와 일반 프로젝트의 시각적 위계가 구분된다.

## 3-2. 프로젝트 카드 개선

- [ ] 카드에 프로젝트 형태를 표시한다: 개인 / 팀 / 실무.
- [ ] 기간을 표시한다.
- [ ] 본인의 역할을 한 줄로 표시한다.
- [ ] 핵심 성과 또는 차별점을 한 줄로 표시한다.
- [ ] 배포 중, 개발 중, 종료 등 상태를 표시한다.
- [ ] 모바일에서도 `자세히 보기` 버튼을 항상 표시한다.
- [ ] 카드 전체를 키보드로 선택하고 열 수 있게 한다.

### 카드 정보 예시

> 부동산 중개보수 계산기  
> 개인 프로젝트 · 기획/디자인/개발 100%  
> 법정 상한 요율과 월세 환산 규칙을 반영한 운영형 계산 서비스

## 프로젝트 상세 템플릿

### 한 줄 요약

이 프로젝트가 누구의 어떤 문제를 해결하는지 한 문장으로 작성한다.

### 프로젝트 정보

| 항목 | 내용 |
|---|---|
| 기간 | YYYY.MM–YYYY.MM |
| 형태 | 개인 / 팀 / 실무 |
| 역할 | 기획 / 디자인 / 프론트엔드 / 백엔드 |
| 기여도 | 담당 범위 또는 비율 |
| 기술 | 핵심 기술 3–5개 |
| 상태 | 운영 중 / 개선 중 / 종료 |

### 문제

- 사용자는 어떤 불편을 겪고 있었는가?
- 기존 방식의 한계는 무엇이었는가?

### 목표

- 무엇을 개선하려 했는가?
- 성공 여부를 어떤 기준으로 판단했는가?

### 내 역할

- 직접 담당한 범위를 구체적으로 작성한다.
- 팀 프로젝트라면 다른 구성원의 역할과 구분한다.

### 핵심 의사결정

- 왜 해당 기술과 구조를 선택했는가?
- 고려한 대안은 무엇이었는가?
- 디자인에서는 어떤 사용자 흐름을 선택했는가?

### 문제 해결

| 문제 | 원인 | 해결 | 결과 |
|---|---|---|---|
| 예시 문제 | 원인 설명 | 적용한 방법 | 개선된 점 |

### 결과와 성과

- 사용자 또는 운영자가 얻은 변화
- 배포 및 운영 여부
- 제작 수, 처리 시간, 성능, 오류 감소 등 수치
- 동료·회사·사용자 피드백

### 회고

- 잘한 점
- 아쉬운 점
- 다시 만든다면 개선할 점

## 개발 면접관용 증거

- [ ] 아키텍처 또는 데이터 흐름 이미지를 추가한다.
- [ ] 상태 관리와 컴포넌트 분리 기준을 설명한다.
- [ ] 기술 선택 이유와 트레이드오프를 설명한다.
- [ ] 가장 어려웠던 버그와 해결 과정을 작성한다.
- [ ] 테스트한 범위와 방법을 작성한다.
- [ ] GitHub 저장소의 README를 정리한다.

## 디자인 면접관용 증거

- [ ] 프로젝트 브리프를 추가한다.
- [ ] 사용자 또는 구매 흐름을 추가한다.
- [ ] 정보 구조와 와이어프레임을 추가한다.
- [ ] 초기안과 최종안 비교를 추가한다.
- [ ] 컬러, 타이포그래피, 컴포넌트 기준을 추가한다.
- [ ] 피드백을 반영한 수정 사례를 추가한다.
- [ ] 실제 게시 또는 운영 화면을 추가한다.

### 완료 기준

- 면접관이 본인의 역할과 팀 전체 결과를 구분할 수 있다.
- 긴 문장만 나열하지 않고 표, 이미지, 짧은 문단으로 빠르게 읽을 수 있다.
- 문제와 해결책이 일대일로 연결된다.
- 최소 하나 이상의 결과 또는 배운 점이 있다.

# Phase 5. About·Skills·Contact 개선

**우선순위:** P1 중요  
**상태:** 대기

## 5-1. About 최신화

- [ ] “개발자를 꿈꾸며 배우고 있다” 중심 표현을 현재의 실행 경험 중심으로 변경한다.
- [ ] 성장 과정은 두세 문장으로 줄인다.
- [ ] 현재 할 수 있는 일과 일하는 방식을 설명한다.
- [ ] 실제 프로젝트 증거와 연결한다.
- [ ] 이모지와 추상적인 수식어 사용을 줄인다.

### 추천 초안

> React와 TypeScript를 중심으로 웹 서비스를 만들고 있습니다. 기획과 디자인 의도를 실제 인터페이스로 구현하는 과정에 강점이 있으며, 사용자 화면뿐 아니라 관리자 기능, 데이터 연결, 배포와 운영까지 경험했습니다. 새로운 분야도 빠르게 구조화해 결과물로 만드는 실행력을 중요하게 생각합니다.

## 5-2. Skills 신뢰도 개선

- [ ] 기술을 `주력`, `프로젝트 사용`, `사용 경험`으로 구분한다.
- [ ] 실제로 설명하기 어려운 기술은 제거하거나 사용 경험으로 이동한다.
- [ ] 기술마다 사용한 대표 프로젝트를 연결한다.
- [ ] 기술 이름 표기를 통일한다: GitHub, GitHub Actions, AWS 등.

### 추천 구조

- 주력: React, TypeScript, Next.js, Tailwind CSS
- 프로젝트 사용: Supabase, Node.js, Express, MySQL, Figma
- 사용 경험: NestJS, Docker, MongoDB, Blender 등

## 5-3. Contact 강화

- [ ] 값이 없는 Instagram 항목을 제거한다.
- [ ] 이메일 보내기 버튼을 추가한다.
- [ ] 이메일 주소 복사 버튼을 추가한다.
- [ ] GitHub 버튼을 추가한다.
- [ ] 이력서 보기 또는 다운로드 버튼을 추가한다.
- [ ] 구직 또는 협업 가능 상태를 표시한다.

### 완료 기준

- 연락처가 비어 있지 않다.
- 방문자가 한 번의 클릭으로 이메일, GitHub, 이력서에 접근한다.

### 완료 기준

- 같은 기능의 버튼이 같은 모양과 문구를 사용한다.
- 사용 언어와 제목 표기 방식이 일관된다.
- 화면을 빠르게 훑어도 각 섹션의 목적이 구분된다.

# Phase 7. 모바일·접근성 개선

**우선순위:** P1 중요  
**상태:** 대기

## 모바일

- [ ] 모바일 햄버거 메뉴 또는 하단 이동 메뉴를 추가한다.
- [ ] 프로젝트 카드에 항상 보이는 상세보기 동작을 제공한다.
- [ ] 프로젝트 상세 제목과 여백을 작은 화면에 맞춘다.
- [ ] 긴 이미지 갤러리의 터치 탐색을 개선한다.
- [ ] 360px, 390px, 768px, 1024px 화면을 확인한다.

## 접근성

- [ ] 클릭 가능한 프로젝트 카드를 button 또는 link로 변경한다.
- [ ] 프로젝트 상세와 이미지 뷰어에 dialog 역할과 이름을 지정한다.
- [ ] ESC 키로 모달을 닫을 수 있게 한다.
- [ ] 모달을 열 때 내부로 포커스를 이동한다.
- [ ] 모달을 닫을 때 기존 카드로 포커스를 돌려준다.
- [ ] 모든 아이콘 버튼에 명확한 접근성 이름을 지정한다.
- [ ] 이미지 대체 텍스트를 `Gallery 1`이 아닌 실제 내용으로 작성한다.
- [ ] 페이지의 대표 제목만 h1으로 사용한다.
- [ ] 키보드만으로 전체 페이지를 탐색한다.
- [ ] 밝은 화면과 어두운 화면의 색상 대비를 확인한다.
- [ ] 애니메이션 감소 설정을 모든 주요 모션에 반영한다.

### 완료 기준

- 마우스 없이 대표 프로젝트를 열고 닫을 수 있다.
- 모바일에서 숨겨진 핵심 메뉴나 기능이 없다.
- 모달을 열고 닫아도 키보드 포커스를 잃지 않는다.

# Phase 8. 성능·SEO·신뢰도 개선

**우선순위:** P2 개선  
**상태:** 대기

## 성능

- [ ] PNG 이미지를 WebP 또는 AVIF로 변환한다.
- [ ] 1MB 이상의 SVG와 PNG를 우선 최적화한다.
- [ ] 2MB 이상인 파비콘을 경량 파일로 교체한다.
- [ ] 카드용 썸네일과 상세용 원본 이미지를 분리한다.
- [ ] 상세 이미지에 지연 로딩을 적용한다.
- [ ] 이미지 width, height 또는 aspect-ratio를 지정한다.
- [ ] 프로젝트 상세 UI를 지연 로딩한다.
- [ ] 번들 분석 후 불필요한 코드를 분리한다.
- [ ] 중복되는 사이트 콘텐츠 요청을 상위 상태 또는 캐시로 통합한다.

## SEO와 공유

- [ ] 페이지 설명 meta 태그를 추가한다.
- [ ] Open Graph 제목, 설명, 이미지를 추가한다.
- [ ] canonical URL을 추가한다.
- [ ] 작성자 정보를 추가한다.
- [ ] 공유용 대표 이미지를 제작한다.
- [ ] sitemap과 robots 설정을 확인한다.
- [ ] Person 또는 ProfilePage 구조화 데이터를 검토한다.

## 품질 확인

- [ ] Lighthouse 모바일 검사를 진행한다.
- [ ] 성능, 접근성, SEO 점수를 기록한다.
- [ ] 주요 버튼과 외부 링크를 모두 확인한다.
- [ ] 404와 데이터 로딩 실패 상태를 확인한다.
- [ ] Chrome, Safari, 모바일 브라우저를 확인한다.

### 완료 기준

- 대표 이미지가 느린 네트워크에서도 과도하게 늦게 나타나지 않는다.
- 공유 시 이름, 설명, 대표 이미지가 정상적으로 표시된다.
- Lighthouse에서 발견된 치명적인 접근성 오류가 없다.
